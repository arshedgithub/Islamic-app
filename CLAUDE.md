# Zikra — Claude Code Guidelines

## Product Rules (apply to every change)

1. **Offline-first**: the core app must not depend on a network connection.
   - Quran text, prayer times, and dhikr must work with airplane-mode on.
   - Network features (mosque finder, sync) must degrade gracefully to an honest "unavailable offline" state.

2. **No streak, guilt, fear, or comparison language** — anywhere in the UI, code, or strings.
   - Banned words/phrases: streak, leaderboard, "you missed", "broken", "falling behind", rank, "days left".
   - Use neutral recovery language: "Pick up where you left off", "Continue today's practice".
   - Test `test/ui_language_guard_test.dart` enforces this; keep it passing.

3. **No invented data** — never show fabricated prayer times, fake counts, or fake reminders.
   - Use honest empty states: "Prayer times coming soon", "No bookmarks yet".

4. **Quran text is never user-editable**.
   - User content (bookmarks, notes) must store only a verse key (`surah:ayah`), never a copy of Arabic text.
   - Quran text is read from the verified local Drift DB, never from user input.

5. **Calm, respectful UI** — touch targets ≥ 48 dp, no dark patterns, no anxiety-inducing colours or animations.

## Folder Conventions

```
lib/
  app/          # app.dart (root widget), router.dart (go_router), theme.dart
  core/
    database/   # app_database.dart + generated files (AppDatabase, Drift)
    services/   # shared singleton services (LocationCacheService, etc.)
    utils/      # pure functions, extensions
  features/
    <feature>/
      data/       # repositories, API clients, stores
      domain/     # models, value objects (no Flutter imports)
      presentation/  # screens, widgets
  l10n/         # app_en.arb, app_si.arb, app_ta.arb
  main.dart

test/           # all tests mirror lib/ structure
docs/           # sprint reports, architecture, decisions
```

## Architecture Decisions (summary — see docs/ARCHITECTURE.md for full detail)

- **State**: flutter_riverpod — providers in feature data/ layer, consumed in presentation/.
- **Routing**: go_router — `StatefulShellRoute` for 5 tabs; named routes for all push screens.
- **Local DB**: Drift (SQLite) — `AppDatabase` in `lib/core/database/`. Schema version tracked.
- **Persistence (small)**: shared_preferences for user settings and simple flags only.
- **Localisation**: flutter_localizations + intl; ARB files in `lib/l10n/`; localeProvider (Riverpod).
- **Backend**: quran.com REST API v4 (read-only, no auth key); Overpass API for mosques. Both are online-only features — their absence must never crash the app.

## Generated Files

`lib/core/database/app_database.g.dart` is generated by build_runner. Commit it to version control (no build step on CI needed beyond running build_runner once).

## Testing Rules

- Every new feature must have at least one unit test.
- Quran data integrity test lives in `test/quran_integrity_test.dart` (Sprint 1).
- `test/ui_language_guard_test.dart` must always pass — do not add banned strings to the allowlist without team review.
- `test/no_fake_prayer_times_test.dart` must always pass — never hardcode HH:MM prayer times in lib/.
